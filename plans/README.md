Confirmed but not planned this batch (next candidates, roughly by leverage):

- **SIRV-12/13** — pairing is unpersisted, invisible outside a modal, and
  survives folder changes it no longer describes; no preview of what will
  transfer. The largest remaining "barely usable" item; needs a
  settings-schema addition and a panel redesign. Plan it as its own batch
  item once 036–038 land.
- **SIRV-04** — no handling of 429/transport errors; a mass failure burns
  through the whole plan. Retry-with-backoff in `Client::authenticated`.
- **SIRV-07/08** — strictly sequential transfers on one client mutex; every
  push re-walks the whole remote tree; uploads hold the file in RAM twice.
- **SIRV-18** — `Client` has no injectable base URL, so readdir/walk/upload/
  download are untestable; push/pull loops are ~60-line near-duplicates.
  This is the enabler for testing 036's readdir guards.
- **CODE-03** — characterization tests on `convert_each`, `convert_to`
  failure paths, `start_conversion`, `parse_args` (039 starts the last).
- **CODE-10** — two duplicate conversion loops; no cancellation, so a large
  run locks the window until it finishes.
- **CODE-08/09** — output-name collision resolution depends on the current
  sort order (outputs can swap identity between runs); `output_path` writes
  beside the source if an entry ever escapes root.
- **CODE-06/07/13** — per-frame full-list scans and per-comparison String
  allocations; `encode_avif` copies full pixel buffers `encode_webp` already
  avoids copying.
- **CODE-04** — table scroll position survives dataset swaps (gallery's was
  fixed; the list's was not).
- **CODE-11** — settings write is the one non-atomic write left; `Display`
  round-trip loses non-UTF-8/whitespace folder paths.
- **CODE-14** — startup scan runs synchronously before the window opens;
  in-app open already does it right in the background.
- **MACOS-03** — auto-update can raise an unexplained admin-password dialog
  at launch (osascript escalation in cargo-packager-updater). New evidence
  appended to decision memo B by plan 035; the ask-first decision stays with
  the maintainer.
- **MACOS-06** — Finder "Open With"/Dock drops arrive via Apple events
  (`on_open_urls`) and are ignored; no `file-associations` metadata.
- **MACOS-08** — the macOS rfd file dialog blocks the render loop; the
  "runs off the main thread" comment at `src/audit/mod.rs:588` is false there.
- **MACOS-10** — CI's macOS job links Homebrew libavif, the exact
  configuration the release job rejects; vcpkg breakage is found on tag push.
- **MACOS-12** — thumbnails decode at 224 logical pixels; every Retina Mac
  shows them upscaled 2x, in an image-quality tool.
- **MACOS-16** — README documents CLI invocations the `.dmg` install cannot
  run without knowing the in-bundle binary path.
- **SIRV-17 (downgraded)** — credentials write is non-atomic with a brief
  default-mode window before chmod. The audit's claim that chmod is skipped
  on macOS was **wrong** (`cfg(unix)` covers macOS); only the misleading
  doc comment at `src/sirv.rs:621-623` and the non-atomic write remain.

  Left as-is, noted in plan 034's out-of-scope.

## Live visual proof contract

The broken Linux headless renderer does not waive UI proof. The reviewer must launch
the real release app, control the `imageguide` window through Hyprland and
`ydotool`/`wtype`, capture it with `grim`, and inspect the PNGs. Keep before/after
captures under the session scratch directory for:

- list and grid at 1100×720 and at the compact supported width;
- selected and unselected rows/tiles, including checkbox toggling;
- comparison at fit and actual size;
- the active conversion or loading state for plans that change those states;
- both a saving projection and a growth projection.

This is a pre-alpha design. Plans may reshape the UI within their stated behavior
and scope; preserving current pixel placement is not a goal.
